# ECC Integration Plan

## 1. Executive Summary

**Retain the existing native OpenCode v2 integration and implement six narrow corrections. Do not reinstall ECC, replace its adapter, or add a discovery framework.** Implementation requires section 10 approval. This audit authorizes no implementation.

The integration is structurally sound: 311 ECC skills coexist with 14 preserved project skills; 27 configured agents including Build and 35 ECC commands use native registries; one bounded v2 adapter supplies advisory hooks. Full skill bodies enter model context on demand. Current upstream main already matches the installed source SHA.

The main problem is always-loaded policy. Fifteen raw common/TypeScript rule files prescribe Claude-specific tools and controls, generic coverage/delegation requirements, and unrelated examples beside this fork's instructions. Correcting this reduces conflicting guidance and startup text. Other changes fix duplicated command arguments, helper examples, deprecated advertising, provenance/regression coverage, and documentation-tool fallback.

Audit verification: **18 adapter tests and 24 skill tests passed**. Private enabled/disabled installed-host smoke passed with zero model calls and no shared-service restart. Full current-HEAD builds, live model selection, all-provider behavior and WSL/Linux runtime were not tested.

## 5. Verified Findings

No P0 defect was established. Each finding includes evidence, practical consequence and a bounded recommendation; static incompatibility is distinguished from observed model failure.

### F-01: Always-loaded rules prescribe incompatible harness behavior

- **P1; High confidence; verified content defect/inefficiency.** No paid conversation was used to demonstrate the model making a wrong call.
- **Upstream:** `U:rules/common/agents.md:5-31` prescribes `Agent(subagent_type: "ecc:planner")`, `/ecc:ecc-guide` and a different roster; common/performance.md gives Claude-only effort/model controls; typescript/patterns.md includes React hooks/generic API envelopes; common/testing.md requires universal 80% coverage and all test classes. common/hooks.md and typescript/hooks.md teach Claude event/config controls.
- **Local:** matching bodies in `.opencode/ecc/rules`; config568-572 includes both raw globs. `L:config/plugin/instruction.ts` reads them as text; it does not enforce their YAML paths fields. Local subagent tool uses configured bare IDs; Effect/Bun/project policies differ.
- **Consequence:** conflicting guidance and approximately6,775 estimated raw-rule tokens, before source wrappers. Precedence prose helps recovery but does not remove contradiction.
- **Improvement:** C-01 removes automatic globs, retains vendor files and uses a concise bridge preserving meaningful security/verification intent. No native loader changes.
- **Benefit/dependency/risk:** clearer ownership and lower startup text; D-01 policy approval required; risk of dropping useful policy. Small effort, Medium risk. Verify T-01/T-02/T-03/T-15.

### F-02: Command wrappers repeat already-present arguments

- **P2; High confidence; verified configuration/substitution behavior.**
- **Sources:** `U:.opencode/commands/*.md`; local matching bodies and config383-566; native `L:config/plugin/command.ts:194-207` replaces every placeholder.
- **Evidence/difference:** all 35 config templates append `$ARGUMENTS`; all 35 referenced bodies already contain it. `/plan` repeats input; some bodies themselves contain several instances.
- **Improvement:** C-02 removes only the config-added suffix. Preserve body/native parser/routing. Do not mechanically delete every internal placeholder.
- **Benefit/dependency/risk:** smaller invoked-task prompt, no startup saving; no dependency; Small effort/Low risk. Verify exact body-based placeholder count, empty/quoted input and native no-placeholder fallback (T-04).

### F-03: Helper examples contradict installed paths, shell syntax and parser

- **P2; High confidence for text/parser mismatch; Medium for model impact.** A model can translate a fenced example, so end-to-end command failure is unverified.
- **Sources:** `U:.opencode/commands/{harness-audit,evolve,projects,promote,instinct-status,instinct-export,instinct-import}.md`, matching local bodies; Python `L:.opencode/skills/continuous-learning-v2/scripts/instinct-cli.py:54-67,2209-2269`; shell selection `L:shell/select.ts:100-114`.

Actual resolver uses absolute CLV2 override, absolute XDG data plus `ecc-homunculus`, otherwise `~/.local/share/ecc-homunculus`. Import/export docs also promise a JSON envelope, while parser/exporter use YAML-like frontmatter plus Markdown blocks (Python515-574,1078-1143); @teammate is not a supported source resolver.
- **Improvement:** C-03 corrects these seven installed command bodies with real relative paths, explicit PowerShell/POSIX examples, supported flags and actual storage precedence. Preserve manual invocation and state.
- **Benefit/dependency/risk:** more reliable instructions; optional Node/Python required; Small–Medium effort/Low risk. T-05/T-06. No observer, wrapper or persistence migration.
